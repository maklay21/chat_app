# Саморевью и ретроперспектива

- Бэкенд: за основу был взят фреймворк FastAPI, с валидацией данных через Pydantic. В целом тут не возникло сложностей, эндпоинты самые базовые. Добавил логгер с хранением в файлах, а также PydanticSettings для удобного и "безопасного" доступа к переменным env

- Redis: написал в отдельном файле класс для доступа к connection pools. Логика такая: есть общий для всех экземпляров класса атрибут _redis_pools. Он хранит объекты redis.ConnectionPool для каждой внутренней бд редиса. Нужно это чтобы коннекты не создавались заного при каждом запросе, а кэшировались.

- Фронтенд: написал несколько функций для нормального отображения (fetchMessages) и отправки (sendMesage) сообщений. Также добавил прокрутку чата к последнему сообщению (scrollToBotom), эффекты для плавного обновления сообщений и прокрутки (useEffect). Трудно было создать похожую кнопку отправк сообщения, поэтому прибегнул к использовани ИИ. Дизайн немного отличается от исходного, но думаю что в целом сделано в том стиле, который был нужен.

- Деплой: использовал docker compose, который содержит 3 сервиса - backend, frontend, redis (image: redis:7-alpine). Также создал два докерфайла для билда бэка и фронта. Фронт запускается с помоощью nmp start, бэк с помощью пакета fastapi[standard] (использую, так как есть простая возможность увеличения числа воркеров FastAPI)
